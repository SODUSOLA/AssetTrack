# Reports and exports

Implements SPEC section 9 (v1.1). The system records no money, so these reports describe repair
activity: what came in, how long it took, who did it, and what is waiting on whom.

All reports are `GET`, under `/api/v1/reports`, and take:

* `format=json` (default), `xlsx` or `pdf`. Excel and PDF are downloads
  (`Content-Disposition: attachment`, `Cache-Control: no-store`);
* `unit_id` (staff only): limit to one unit.

| Report | Parameters | Answers |
|---|---|---|
| `monthly-activity` | `month=2026-10` | What happened to repairs this month, per unit and per device |
| `open-tickets` | | The backlog now, by unit, priority and age, and what waits on the unit |
| `turnaround` | `from`, `to` | How long repairs take (days), per unit and per repair |
| `repeat-faults` | `from`, `to`, `min` | Devices that keep coming back |
| `awaiting-unit` | `include_recent` | Overdue acknowledgements, unanswered disputes, resolved tickets nobody confirmed |

Who sees what: admin, engineer and auditor see every unit; a unit rep gets the same reports for
their own unit only (a `unit_id` they send is ignored).

## The shape of a report

Every report, in every format, comes from one object:

```jsonc
{
  "key": "monthly-activity", "title": "Monthly repair activity", "period": "October 2026",
  "scope": {"unit_id": null, "label": "All units"},
  "generated_at": "2026-11-10T11:00:00Z", "generated_by": {"id": "...", "full_name": "..."},
  "summary": [{"key": "received", "label": "Devices received for repair", "value": 5}],
  "sections": [{
    "key": "by_unit", "title": "By unit",
    "columns": [{"key": "unit", "label": "Unit", "type": "text"},
                {"key": "avg_days", "label": "Average days to return", "type": "number"}],
    "rows": [{"unit": "Unit A", "avg_days": 4.6}],
    "totals": {"unit": "Total", "avg_days": 3.9},
    "note": "Turnaround counts repairs returned in the month, from intake to return."
  }]
}
```

Column types are `text`, `int`, `number` (one decimal), `date` (`2026-10-05`) and `datetime`
(Lagos wall-clock time with offset, `2026-10-05T14:30+01:00`). A front end can render any report
from this, without knowing which one it is.

## Definitions

* **Dates are Africa/Lagos days.** A month starts at Lagos midnight, so a return at 00:15 on
  1 Oct belongs to October even though it is still 30 Sep in UTC. `from` / `to` are inclusive and
  default to the last 90 days; periods longer than five years are refused.
* **A repair cycle** is one `received_for_repair` event paired with the next `returned_to_unit` of
  the same device. Days = return minus intake. Repairs that ended in decommissioning, or are not
  back yet, are not turnaround figures.
* **Rounding.** Durations are computed from exact times and rounded to one decimal at the end. The
  overall average is over all repairs, not the average of the unit averages.
* **In the workshop at month end** is reconstructed from the event log as it stood then (the
  statuses from "received for repair" through "repaired, waiting for collection").
* **Tickets opened / closed** use the ticket's creation and closing time. A ticket that was
  reopened later no longer has a closing time.
* **An unanswered dispute** is a disputed return whose ticket is still `reopened`, or any other
  disputed event that engineering has not corrected with a `note_added` event.
* **Overdue** means older than `ACK_OVERDUE_DAYS` (default 3). Nothing is ever confirmed on a
  unit's behalf; these reports only make the waiting visible.

## Exports

* **Excel:** a Summary sheet plus one sheet per section, with a frozen header row, filters, real
  numbers and dates, bold totals, and a print footer. Text is always stored as text, so a device type
  or any name written as `=HYPERLINK(...)` can never run as a formula.
* **PDF:** landscape A4, one table per section, "Generated by <name> on <date>" and the page
  number on every page. Text from users is escaped, so `<b>` is printed, not interpreted.
* Names with accents (Ọlá, Ẹ̀jẹ̀) need a Unicode font: the Docker image installs DejaVu, macOS uses
  Arial. Without either, accents are simplified rather than printed as boxes.

Excel and PDF are rendered from the same object as the JSON, and tests read the generated files
back to check they carry the same figures.
